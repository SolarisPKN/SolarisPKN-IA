# Public/private boundary

## Public repository

Safe categories:

- architecture documents;
- schemas and interfaces;
- generic policy examples;
- synthetic fixtures;
- tests using fake data;
- provider-neutral adapters;
- educational diagrams;
- implementation guides.

## Private installation

Keep private:

- persona/personality;
- memory database;
- session/event logs;
- chat history;
- personal projects and relations;
- credentials;
- machine inventory;
- device identities;
- local provider configuration;
- user-specific rules;
- private skills derived from personal work.

## Rule

Do not mirror or symlink the private data root into the public repository. Export only reviewed, sanitized artifacts.
